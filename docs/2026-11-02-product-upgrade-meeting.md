# CTO·CPO·CMO·CSO 제품 고도화 회의 및 적용 범위

## 결론

네 제품을 작은 팀의 **고객 상담 → 수주 → 프로젝트 → 팀 업무·결재 → 검수·승인보고** 흐름으로 강화한다. 경쟁사의 모든 유료 플랜 기능과 동등하다고 표기하지 않는다. 실제 저장·권한·이력이 있는 업무 흐름을 기본선으로 삼는다.

- **CPO:** 기능 수보다 업무의 완료 기준을 우선한다. 회사 변경·로그아웃 후 자료 격리, 내보내기 범위 일치, 최신 보고 버전 판단을 수용 기준으로 정한다.
- **CMO:** ‘업계 유일한 연동’ 대신 ‘다음 담당자가 해야 할 일을 놓치지 않도록 연결한다’는 고객 효용을 설명한다. 공개 화면·소개서와 로그인 후 실행을 구분한다.
- **CSO:** 기존의 명시적 데이터 연결을 재사용해 인수인계 점검을 차별 기능으로 제공한다. 권한 부족·미설정을 누락 확정으로 판단하지 않는다.
- **CTO:** 신규 테이블·권한 확대 없이 기존 명령과 RLS를 활용한다. 클라우드 보고 저장·검수 프런트 연결을 우선하고, 조작 검증과 DB 검증을 구분한다.

각 공급자의 공개 기능 설명을 참고한 비교이며 실제 모든 플랜을 직접 사용한 평가나 시장 점유율 분석은 아니다. ‘기능 없음’은 본 저장소의 구현 범위 기준이다.

## 이번 적용

1. **Flownote:** 회사 계정 화면에서 CSV 검사 → 고객·캠페인·기간·제외 행 확인 → 서버 합계 재계산·버전 저장 → 독립 검수 → 승인본 HTML/합계 CSV → 수동 전달 기록. 이전 버전은 유지한다.
2. **ProjectFlow:** 여러 프로젝트·작업을 제목·상태·담당자·기한으로 검색하는 운영 플래너, 월간 일정·모바일 일정 목록, 필터 범위 CSV·ICS 내보내기.
3. **Follonote:** 고객별 상담·기회·후속 연락의 통합 타임라인, 이메일·전화·회사명 중복 후보 안내, 연락·기회 운영 플래너. 중복 자동 병합이나 과거 단계 변경 이력을 추정하지 않는다.
4. **Crewmemo:** 월간 일정·마감 플래너, 비용 사용·외부 업무·프로젝트 변경 요청 양식, 기존 지정 결재자 검증을 유지한 실제 요청 저장.
5. **제품 연결:** 수주 후 프로젝트 연결, 작업 담당·기한, 명시적으로 연결된 팀 작업 상태, Flownote 최신 보고 상태의 **인수인계 점검**. 원본 링크로 이동하며 자동 승인·전달은 하지 않는다.
6. **로그인 필수:** 네 제품·샘플·CSV·제품 연결의 업무 화면은 인증 확인 후 연다. 공개 랜딩·상품 설명·소개서는 유지한다. 화면을 숨기는 것과 실제 자료 보호는 구분하며, 실제 회사 자료는 서버 명령·RLS로 계속 제한한다.
7. **계정별 샘플:** 기존 익명 브라우저 캐시를 자동 재사용하지 않고 사용자 ID별로 샘플 저장 공간을 분리한다. 로그아웃 시 제품 컴포넌트를 내리고, 인증 갱신·복귀에서 로그인 상태를 확인한다.

## 검증 범위

- 단위·도메인 테스트: CSV 회사/프로젝트 범위·행 수 대조, 승인본 출력, 권한별 전이, 월간 날짜, 필터, CSV 수식 주입 방지, ICS 이스케이프·줄 접기·종료일, 중복 후보, 인수인계의 최신 버전·권한 불명 구분, 사용자별 샘플 키.
- 실제 DB: `verify-cloud-report-transaction.sql`에서 합계, 자기 승인 거부, 외부 회사 접근 거부, 독립 검수, 전달 이력, v2 초안·이전 스냅샷 보존, RLS 확인. 합성 사용자·자료는 전체 롤백했고 잔여 검증 계정은 0개다.
- 브라우저: 실제 빌드에서 익명 제품/샘플/CSV/연결 접근이 로그인 화면으로 차단되는지 확인. 별도 로컬 컴포넌트 테스트에서 플래너 필터·월간/모바일 전환, 타임라인, 결재 양식 저장, 클라우드 보고 CSV 검사·초안·검수 요청 조작을 확인한다. 이 컴포넌트 테스트의 Auth/보고 API mock을 운영 HTTP 로그인 검증으로 표현하지 않는다.
- Supabase 보안 advisor: 검사 시 지적 항목 없음. 이것을 종합 보안 인증으로 해석하지 않는다.

## 남은 격차와 운영 제약

- 전사 회계·급여·재고, 작업 의존성·하위 작업·간트, CRM 이메일 연동·자동 배정·중복 병합, 다단계 결재·부재 위임·반복 일정·자원 예약은 아직 구현하지 않았다.
- ICS는 일회성 복사이며 양방향 캘린더 동기화가 아니다. 메일·푸시 자동 알림과 결제는 실행하지 않는다.
- 일반 고객용 SMTP가 준비되지 않아 신규 가입 확인 메일에 제한이 있다. 이메일 확인을 마친 기존 계정 로그인과 회원가입/메일 발송 전체 검증은 구분한다.
- 새 화면부터 실제 브라우저 로그인·역할 전환·파일 입력·DB 저장·승인본 다운로드까지 하나로 묶는 인증 HTTP 종단 검증, 부하·장애 복구, 실제 iOS/Android 기기 검증은 완료로 표시하지 않는다.
- 현재 공개 체험판의 정적 샘플·소개 파일은 합성 자료다. 로그인 화면을 추가했다고 공개 JavaScript·소개 PDF·합성 샘플 자체를 비공개 저장소로 간주하지 않는다. 실제 회사 자료를 해당 정적 파일에 넣지 않는다.

후속 우선순위는 **실제 인증 HTTP 종단 검증 및 SMTP → 작업 의존성·하위 작업 → 반복 업무·담당 알림 → 다단계 결재/CRM 이력** 순으로 잡는다. 완성 제품과 동등하다는 홍보보다 실제 고객 파일럿에서 처리 가능한 업무 범위를 제시한다.
