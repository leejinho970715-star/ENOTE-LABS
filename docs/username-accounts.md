# 이름·아이디·비밀번호 가입

2026-11-03. 네 제품은 동일 Supabase Auth 사용자 ID와 기존 회사별 권한을 사용한다. 새 가입은 이름·아이디·비밀번호만 받고 이메일 인증/발송을 사용하지 않는다. 기존 이메일 계정의 비밀번호 로그인은 유지한다. ENOTE-LABS의 제품 실행 링크는 같은 도메인의 제품 경로를 사용해 로그인 저장소를 공유한다. 기존 독립 제품 도메인에서도 같은 자격으로 로그인할 수 있지만 브라우저 저장소는 origin별로 구분된다.

## 서버 경계

- 공개 `username-signup` Edge Function이 요청 형식, 공개 API 키, origin, 본문 크기, 비밀번호 조건과 가입 요청량을 검사한다. 공개 가입 요청에는 기존 사용자 JWT가 없으므로 이 함수만 `verify_jwt=false`이다. 업무/관리 RPC의 인증을 해제한 것이 아니다.
- Auth Admin API의 `createUser`로 내부 식별 주소를 생성하며 service-role 키는 Edge Function 기본 서버 환경변수에서만 읽는다. 이 주소는 실제 이메일 소유 인증이 아니다. 전역 이메일 확인 설정은 끄지 않았다.
- 사용자 수정 불가능한 app_metadata의 계정 유형/아이디와 내부 주소의 일치 여부를 DB가 확인한다. 비공개 아이디 레지스트리에 사용자 UUID를 연결한다. 표시 이름은 권한 판단에 쓰지 않는다.
- Auth Admin이 행 삽입 후 trusted app_metadata를 적용하므로 검증은 트랜잭션 종료 시점의 최종 행으로 수행한다. 공개 native signUp으로 user_metadata만 위조해 내부 아이디를 선점하는 요청은 거부한다. 이 검증을 단순 제거하지 않는다.
- 대표 아이디 `dudrhkddmlcn`의 최초 생성에는 기존 관리자 비밀번호를 추가 확인하고, 성공 시 해당 Auth UUID를 대표로 바인딩한다. 일반 계정은 운영 관리자 역할을 얻지 않는다. 대표만 다른 관리자를 지정한다. 대표의 실제 비밀번호 입력과 계정 생성은 사용자에게 맡긴다.
- 비공개 레지스트리/등록 제어 RPC는 service_role 전용이며 일반 로그인 회원과 익명 이용자에게 직접 실행·조회 권한이 없다.
- 가입은 IP 식별 HMAC당 8회/15분, 전체 100회/15분, 대표 아이디 등록 5회/15분으로 제한한다. 프록시 IP 판별은 플랫폼 전달 헤더에 의존하며 유일한 방어로 간주하지 않는다. 전역 한도는 별도 적용된다. 제한 기록은 다음 가입 요청 때 1일 이전 행을 정리한다.
- 비밀번호/관리자 비밀번호를 애플리케이션 로그에 출력하지 않는다. Auth 비밀번호 해시는 인증 서버가 관리하며 공개 코드·설정에 service-role 키를 포함하지 않는다.

## 사용자 화면

- Flownote 회사 계정, CSV/샘플 로그인 게이트, PMS/CRM/그룹웨어/제품 연결/관리자 페이지의 공통 로그인에 아이디 입력을 적용했다.
- React 제품은 공통 게이트에서 직접 회원가입할 수 있다. 내부의 중복 이메일 가입 폼을 제거했다.
- 회원 연결/관리자 지정 입력은 아이디를 받으며 기존 이메일 계정도 연결할 수 있다. 고객 연락처의 실제 이메일 필드는 변경하지 않았다.
- 관리자 입장 버튼은 랜딩의 우측 하단에 고정하며, 모바일 safe-area와 44px 이상 조작 영역을 적용했다.
- 이름/아이디/비밀번호만으로는 이메일 기반 자동 복구를 제공할 수 없다. 현재 분실 계정은 운영자 문의와 적절한 본인·회사 권한 확인이 필요하며 아이디를 안다는 이유로 비밀번호를 재설정하지 않는다.
- 개인정보/약관 및 제품 사용 가이드에서 새 가입의 이메일 인증 요구를 제거했다. 국외 개인정보 처리 조건의 운영 확인은 기존과 같이 남아 있다.

## 검증

- 단위 및 기존 회귀 테스트 59개 통과.
- 실제 Edge Function HTTP: 잘못된 origin/API 키/아이디 거부, 대표 아이디 무단 등록 거부, 정상 가입, 대소문자 중복, 잘못된 비밀번호 거부, Auth 세션 확인·갱신, 위조 role 무시, 운영 관리자 역할 없음, Flownote 회사와 공통 Studio 회사 생성, 네 제품의 권한 있는 데이터 조회 통과.
- 운영 DB 트랜잭션 검증: 공개/일반 회원의 등록 RPC 호출 불가, 비공개 레지스트리 조회 불가, user_metadata 위조 내부 주소 생성 차단, 대표 등록 비밀번호 확인과 UUID 역할 바인딩, 가입 요청 한도 통과. 합성 자료와 설정 변경은 전부 롤백.
- 브라우저에서 실제 합성 계정으로 PMS 로그인 → CRM → 그룹웨어 → Flownote 회사 데이터 이동 시 로그인 유지, 로그아웃 후 회사 자료 제거를 확인했다. 모바일 390px 가입 화면에 이메일 필드가 없고 가로 넘침이 없으며, 버튼 높이 44px/간격 12px를 확인했다. 대표 아이디 입력 시 추가 확인 필드만 표시된다.
- 대표 실제 계정 생성/로그인은 사용자가 비밀번호를 직접 입력하기 전까지 미검증이다. 테스트 계정 정리와 운영 배포 결과는 작업 최종 보고에서 별도로 확인한다.
